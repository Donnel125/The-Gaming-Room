## CS 230 Project Reflection

### Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room wanted to expand *Draw It or Lose It* from Android to a web-based game that works across Windows, Linux, macOS, and mobile devices. The system needed to support multiple players and teams, ensure unique game and team names, and be secure, scalable, and maintainable.

### What did you do particularly well in developing this documentation?

I clearly evaluated the operating platforms and explained why Linux was the best choice. I also connected object-oriented design principles and the Singleton pattern to the client's requirements.

### What about the design document was helpful when developing the code?

The design document provided a roadmap for the project. It helped organize the classes, relationships, and design patterns before coding, making implementation much easier.

### If you could revise one part, what would you improve?

I would expand the system architecture section by adding a diagram to better illustrate how the clients, server, and database interact.

### How did you interpret the user's needs and implement them into your software design?

I focused on creating a secure, scalable application that supports multiple users and works across different platforms. Meeting the user's needs is essential because it ensures the software is useful, reliable, and easy to maintain.

### How did you approach designing software?

I started by analyzing the requirements and selecting the best architecture and design patterns to meet them. In future projects, I will continue using requirements analysis, UML diagrams, and iterative planning before writing code.
